# the jct collective

An editorial website for an independent, founder-led strategy and creative studio. Built with Next.js App Router, React, TypeScript, Tailwind CSS, Motion, and Lucide. No database, analytics, paid services, or contact-form backend.

## Develop

Use Node.js 22 or newer (validated on Node 24) and npm. Work in the existing `/workspace/thejctcollective` checkout; an additional worktree is unnecessary.

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
```

The development server uses port 3000. Visit it in your local browser when running locally. To verify a production build:

```sh
npm run lint
npm run typecheck
npm run build

```

In this cloud environment use local HTTP requests for readiness; onboarding does not provide public localhost preview links. Development processes must restart in new sessions. Production is a static export; see GitHub Pages hosting below.

## Pages and content

- `/`: introduction, original artwork, studio, capabilities, spotlights, audiences, approach, and contact.
- `/studio`: personal founder-led positioning and working philosophy.
- `/expertise`: nine offerings across strategy, creative, and digital.
- `/inquiries`: direct email, encoded inquiry subject/message, and copy-email interaction with manual selection fallback.
- `/work/[slug]`: published case studies only; drafts and unknown slugs return 404.

Edit `src/content/site.ts` for the email, description, founder name/biography, services, spotlights, audiences, and principles. The founder fields are intentionally empty until approved information is supplied. Longer page-specific copy lives in the corresponding `src/app/*/page.tsx` files. Edit `--accent` and other design tokens at the top of `src/app/globals.css` to change the palette. Maintain accessible contrast.

Original typographic artwork is generated by `Artwork` in `src/components/editorial.tsx`. It is decorative and does not represent client deliverables. To replace it with approved photography, put local assets in `public/images/` and use `next/image` with descriptive alt text, correct dimensions, and an intentional crop. Do not commit private or unlicensed material.

## Publish a project

Edit `src/content/projects.ts`. Replace all bracketed draft fields with approved facts, add client/year/services and local image paths, and include meaningful gallery alt text. Keep `status: 'draft'` until approved. Set `status: 'published'` to expose its route and sitemap entry. `ProjectCard` and `CaseStudy` are reusable templates. The homepage currently shows capability spotlights; replace that section with `publishedProjects` and `ProjectCard` when approved work exists. Never publish fabricated results or client information.

## Domain and metadata

Copy `.env.example` to `.env.local` if configuring the domain locally. Set `NEXT_PUBLIC_SITE_URL` to the real HTTPS origin in the deployment environment before building. Until supplied, the site emits no invented canonical domain and the sitemap is empty. Metadata uses Next.js APIs; the social image and favicon are original wordmark graphics. No business address or reviews are invented.

## GitHub and Vercel launch

1. Review changes with `git status` and `git diff`. Commit the approved site and push your branch to the connected GitHub repository using your normal authorized Git workflow.
2. Import the repository into Vercel, choose the Next.js preset, and use the repository root. Install with `npm ci`, build with `npm run build`. This site uses a static export; use `out` as the output directory if prompted.
3. Add `NEXT_PUBLIC_SITE_URL` with the real production origin. No application secrets are required.
4. Connect your domain in Vercel and configure the DNS records Vercel provides. Redeploy after changing build-time site configuration.
5. Verify all four pages, mobile navigation and keyboard behavior, email address/subject, clipboard fallback, social image, canonical metadata, sitemap, robots, and draft 404s over HTTPS.

Deployment and external services are not performed by this build. Confirm founder information, approved assets, and the production domain before launch. Lighthouse scores and real-world Core Web Vitals require deployment measurements; no scores are claimed here.

## GitHub Pages hosting

The site now exports static HTML into `out/`. The workflow in `.github/workflows/pages.yml` builds and deploys it on pushes to `main`.

In the GitHub repository, open **Settings → Pages → Build and deployment → Source → GitHub Actions**. Then open **Actions → Deploy website to GitHub Pages → Run workflow** if the first run needs to be retried. GitHub will show the actual site address when deployment finishes. A repository site normally uses `https://wdhvh7tzng-stack.github.io/thejctcollective/`.

The workflow derives `NEXT_PUBLIC_BASE_PATH` and `NEXT_PUBLIC_SITE_URL` from GitHub Pages settings, including custom domains. Do not hard-code a different production origin in GitHub. Local development needs neither variable. For a local static build matching the repository path:

```sh
NEXT_PUBLIC_BASE_PATH=/thejctcollective NEXT_PUBLIC_SITE_URL=https://wdhvh7tzng-stack.github.io/thejctcollective/ npm run build
```

Serve `out/` using a static HTTP server with that directory mounted at `/thejctcollective/`. Static output does not use `npm start`; use `npm run dev` for normal development. Images use Next's unoptimized setting because GitHub Pages has no image-processing server. All published case-study slugs are generated at build time; publishing requires a rebuild. When no projects are published, the internal build-only fallback resolves to not-found content and never enters the sitemap or listings.

## Hand & Stone case study

The published `/work/hand-and-stone/` entry in `src/content/projects.ts` adapts the uploaded advertising recommendations into the site's editorial design. It includes the audience, research approach, strategic insight, four proposed activations, and campaign-language studies. It is labeled as a strategy and creative proposal; no implemented partnership or measured campaign results are claimed. No collaborator credits are displayed.

The homepage's first work module links to this case study; the second remains a capability spotlight. Change the project's `featured` flag to control homepage inclusion. Update recommendations and campaign lines in the project entry. Artwork is rendered as HTML/CSS in `src/components/projects.tsx`; original slide images and interview transcripts are not uploaded to the public website. Images added later should use local `/images/...` paths, which the case-study components prefix for GitHub Pages.
